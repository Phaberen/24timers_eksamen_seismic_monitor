When delivering each code snippet:
- **Very brief explanation.** A line or two max. The user will ASK for more if needed. Do not give per-method walkthroughs or bulleted "key points" by default. (This narrows the "explain method-by-method" instruction in [[no-claude-traces-copy-paste-workflow]].)
- **Code comments = clear, concise, good-practice, like a good dev would write.** Plain professional comments only. NO exam/oral framing — never write "for the oral", "graded", "defensible at the exam", etc. in code or prose. That framing doesn't help.

**Why:** The verbose explanations and exam-flavored comments were noise, not help.
